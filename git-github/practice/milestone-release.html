실전 · P07 · GitHub 협업

Milestone과 릴리스

Milestone(마일스톤)은 '언제까지 이만큼'을 묶는 날짜 기반 목표예요. v1.0 오픈 마일스톤의 진행률 바가 어떻게 채워지는지 보고, 비슷해 보이는 Iteration·Label과 어떻게 다른지, 그리고 PR #57 하나가 병합되면 이 바가 어떻게 한 칸 올라가는지까지 이어볼게요.

비유

Milestone은 여행 일정표의 '3일차: 부산 도착' 같은 중간 목표예요. 그 날짜까지 해야 할 일들을 한 봉투에 담아두고, 봉투에는 "12개 중 7개 완료"처럼 진척이 표시돼요. 봉투 안 일들이 하나씩 끝날수록 채워지는 막대를 보며, 마감까지 얼마나 왔는지 가늠하는 거예요.

v1.0 오픈 마일스톤

아래는 v1.0 오픈 마일스톤이에요. 마감일(Due by), 완료율, 진행률 바, 그리고 열려 있는 항목과 닫힌 항목 개수가 한 카드에 모여 있어요. 지금은 전체 12개 중 7개가 닫혀 58%까지 찼어요. 이 숫자가 어떻게 나오는지 곧 짚어볼게요.

어디로 들어가나

마일스톤 목록은 이슈나 PR 목록 화면에서 들어가요. Issues(이슈) 또는 Pull requests(풀 리퀘스트) 탭을 연 뒤, 목록 오른쪽 위의 Milestones(마일스톤) 버튼을 누르면, 저장소의 모든 마일스톤이 진행률 바와 함께 죽 나와요. 거기서 v1.0 오픈을 누르면, 그 마일스톤에 묶인 이슈·PR만 모아 볼 수 있어요.

새 마일스톤은 그 목록 화면의 New milestone(새 마일스톤)으로 만들고, 제목·마감일·설명을 적어요. 그다음 개별 이슈·PR의 사이드바 Milestone 칸에서 이 마일스톤을 골라 붙이면 돼요.

진행률 바는 어떻게 채워질까

진행률 바는 어렵게 생각할 것 없어요. 닫힌 항목 ÷ 전체 항목(이슈·PR 모두 포함)으로 표시됩니다. v1.0 오픈은 전체 12개(열린 5 + 닫힌 7) 중 닫힌 게 7개라, 바가 7/12만큼 채워져 있는 거예요.

여기서 '항목'은 이슈만이 아니라 PR도 함께 센다는 점만 기억하면 돼요. 마일스톤에 붙은 PR이 병합되어 닫히면, 그것도 '닫힌 항목' 한 개로 세어져 바가 올라가요.

팁

진행률은 "몇 개 중 몇 개가 닫혔나"를 보여주는 개수 기준이에요. 큰 이슈든 작은 이슈든 한 개는 한 개로 세어져요. 그러니 바가 절반이라고 해서 "일의 무게가 딱 절반 남았다"는 뜻은 아니에요. 남은 항목 중에 무거운 게 있을 수 있으니, 숫자와 함께 남은 목록도 같이 보는 게 좋아요.

Milestone · Iteration · Label, 언제 무엇을

세 가지가 "일을 묶는다"는 점에서 비슷해 보이지만, 묶는 기준이 달라요.

  • Milestone(마일스톤) — 날짜 기반 목표를 묶어요. "8월 14일 v1.0 오픈까지"처럼 마감이 있는 한 덩어리의 릴리스·목표에 써요. 진행률 바가 딸려 와요.
  • Iteration(반복) — 반복되는 스프린트 주기를 묶어요. "이번 주", "다음 2주"처럼 계속 돌아오는 기간 단위로 일을 나눌 때 써요. Projects의 필드예요.
  • Label(라벨) — 시간과 무관한 분류예요. bug, priority:high처럼 성격·종류로 붙이는 꼬리표라, 여러 개를 겹쳐 달 수 있어요.

정리하면, 마감이 있는 한 번의 목표는 마일스톤, 돌아오는 주기는 반복, 성격 분류는 라벨이에요. #42에 붙은 v1.0 오픈은 마감이 있는 릴리스라서 마일스톤이 맞아요.

PR #57이 병합되면 바가 움직여요

이제 앞 페이지들의 이야기가 여기서 하나로 이어져요. 흐름을 되짚어 볼게요.

  • 지원 님이 「로그인 버튼이 안 눌려요」 이슈 #42를 열었고, 여기에 v1.0 오픈 마일스톤이 붙어 있어요.
  • 민수 님이 이 문제를 고친 PR #57을 올렸고, 본문에 Closes #42가 적혀 있어요.
  • 하늘 님의 리뷰가 끝나고 PR #57이 병합되면, 닫기 키워드 덕분에 이슈 #42가 자동으로 닫혀요.
  • #42가 닫히는 순간, 마일스톤의 '닫힌 항목'이 하나 늘어요. 그래서 진행률 바가 7/12(58%)에서 8/12로 올라가요.

즉 위 mock의 58% 바는 PR #57이 병합되기 직전의 모습이에요. 리뷰 하나, 병합 하나가 이슈를 닫고 마일스톤 숫자를 밀어 올리는 이 연결이, GitHub 협업의 뼈대예요.

알아두면 좋은

여기서 말한 자동으로 닫히는 규칙은 앞서 P04에서 다룬 것과 같아요. Closes #42 같은 닫기 키워드는 그 PR이 default 브랜치를 대상으로 할 때만 이슈를 자동으로 닫아요. PR #57은 fix/login-hitbox → main이라 default 브랜치가 맞으니, 병합과 동시에 #42가 닫히고 바가 움직여요.
