실전 · P06 · GitHub 협업

보드 운영: 뷰·필드·자동화

Projects는 이슈와 PR을 한눈에 늘어놓고 옮기며 관리하는 '작업 현황판'이에요. 도서관 리뉴얼 보드에서 카드를 직접 옮겨보고, 같은 데이터를 다르게 보는 뷰, 카드에 붙는 필드, 항목을 넣는 방법, 그리고 손을 덜어주는 자동화까지 짚어볼게요.

비유

Projects 보드는 주방의 주문표 레일과 똑같아요. 새 주문은 '대기'에 붙고, 요리가 시작되면 '조리 중'으로, 다 되면 '나감'으로 표를 왼쪽에서 오른쪽으로 밀어 옮기죠. 누가 봐도 지금 무엇이 어디까지 왔는지 한눈에 보여요. GitHub Projects도 이슈·PR이라는 '표'를 열에서 열로 옮기며 진행 상황을 드러내요.

도서관 리뉴얼 보드 옮겨보기

아래는 도서관 리뉴얼 보드예요. 열이 네 개(Todo·In Progress·Review·Done) 있고, 카드 하나가 이슈나 PR 하나예요. 카드를 클릭(또는 키보드로 Enter)하면 다음 열로 옮겨가고, 카드 안의 Status(상태) 값과 열 위의 개수도 같이 바뀌어요. 지원 님이 「대출 연장 기능」을 Todo에서 오른쪽으로 밀어보세요. 칸반은 이렇게 '표를 옮기는' 게 전부예요.

github.com/dongne-library/library-web
Todo 0
대출 연장 기능 #38
지 지원
Status: Todo
In Progress 0
로그인 버튼이 안 눌려요 #42
민 민수
Status: In Progress
Review 0
로그인 버튼 클릭 영역 수정 PR #57
하 하늘 리뷰 중
Status: Review
Done 0
팁

보드가 처음이라면 칸반 개념부터 짚고 오면 편해요. T23 칸반보드(Projects)에서 열·카드·흐름의 기본을 그림으로 다뤄요. 이 실전 페이지는 "그래서 화면에서 어디를 누르나"에 집중해요.

같은 데이터, 다른 뷰

Projects의 핵심은 데이터는 하나인데 보는 방식은 여러 가지라는 점이에요. 위에서 옮긴 카드들은 그대로인데, 상단의 뷰 탭만 바꾸면 전혀 다른 모양으로 같은 항목을 보여줘요.

  • Board(보드) — 방금 본 열-카드 칸반이에요. 상태별로 늘어놓고 옮기기 좋아요.
  • Table(표) — 엑셀처럼 한 줄에 한 항목, 열에 필드값이 놓여요. 값을 한꺼번에 훑고 채우기 좋아요.
  • Roadmap(로드맵) — 날짜 축 위에 항목을 막대로 펼쳐요. "언제부터 언제까지"를 볼 때 써요.

뷰는 여러 개를 저장해 둘 수 있어요. 이렇게 조건을 걸어 저장해 둔 화면을 saved view(저장된 뷰)라고 해요. "내 담당만 보는 표", "이번 주 로드맵"처럼 자주 쓰는 화면을 탭으로 남겨두는 거예요.

카드에 붙는 필드

카드(이슈·PR)에는 GitHub 기본 정보 말고도, 보드에서 직접 만드는 커스텀 필드를 붙일 수 있어요. 위 카드의 Status도 그런 필드 중 하나예요. 만들 수 있는 필드 종류는 이래요.

  • Text(텍스트) — 자유롭게 적는 메모칸.
  • Number(숫자) — 우선순위 점수, 예상 규모 같은 수치.
  • Date(날짜) — 마감 예정일 같은 날짜 하나.
  • Single select(단일 선택) — Status처럼 정해둔 보기 중 하나를 고르는 칸.
  • Iteration(반복) — 한 주·두 주 같은 반복 주기를 붙이는 칸. 스프린트 단위 관리에 써요.

여기에 더해, 이슈끼리의 관계에서 자동으로 채워지는 필드도 있어요.

  • Parent issue(상위 이슈) — 하위 이슈가 어느 부모에 속하는지 보여줘요.
  • Sub-issue progress(하위 이슈 진행률) — 부모 카드에 "3개 중 1개 완료" 같은 진행 막대가 떠요. 이슈 #38의 1/3이 여기에 나타나요.

Group by · Slice by · 합계

필드를 만들었으면, 그 필드로 화면을 묶고 나눠 볼 수 있어요.

  • Group by(그룹 기준) — 고른 필드값끼리 항목을 묶어요. Status로 그룹하면 방금 본 보드처럼 상태별 묶음이 되고, Assignees(담당자)로 그룹하면 사람별 묶음이 돼요.
  • Slice by(슬라이스) — 화면 왼쪽에 값 목록을 세워두고, 하나를 누르면 그 값에 해당하는 항목만 걸러 보여줘요. 큰 보드에서 "지금은 이 라벨만" 하고 좁혀 볼 때 편해요.
  • Field sums(필드 합계) — 열 머리에서 숫자 필드를 합산해요. 예상 규모 점수의 합 같은 걸 열별로 볼 수 있어요.
  • Insights(인사이트) — 보드 데이터를 막대·선 차트로 그려, 시간에 따른 변화를 보여줘요.
주의

모든 필드로 Group by(그룹 기준)를 걸 수 있는 건 아니에요. title(제목), labels(라벨), reviewers(리뷰어), 그리고 linked PR(연결된 PR) 필드로는 그룹을 나눌 수 없어요. 라벨은 한 항목에 여러 개가 붙을 수 있어 하나의 묶음으로 딱 나뉘지 않기 때문이에요. 이 네 가지로 묶으려다 안 되면 "고장"이 아니라 원래 그래요.

항목을 보드에 넣는 4가지 길

이슈나 PR을 보드에 올리는 방법은 네 가지예요. 손으로 넣는 길 셋, 자동으로 들어오게 하는 길 하나예요.

  • 이슈 사이드바의 기어(⚙) — 이슈 화면 오른쪽 Projects 칸의 기어를 눌러 이 보드를 고르면 카드로 올라와요.
  • 프로젝트의 + 버튼 — 보드 맨 아래 +로 기존 이슈를 검색해 붙이거나, 새 항목을 바로 적어 넣어요.
  • Auto-add(자동 추가) 워크플로 — "이 라벨이 붙은 이슈는 자동으로 이 보드에" 같은 규칙을 걸어두면 손대지 않아도 들어와요.
  • gh project item-add — 터미널에서 명령 한 줄로 항목을 추가해요. 자동화 스크립트에서 자주 써요.

한 프로젝트에는 항목을 최대 50,000개까지 담을 수 있어요. 웬만한 팀은 부딪힐 일이 없는 넉넉한 한도예요.

손을 덜어주는 자동화

보드에는 내장 자동화(워크플로)가 있어서, 정해진 일이 벌어지면 카드를 알아서 움직여줘요. GitHub이 공식으로 확정해 둔 것 중, 마음 놓고 믿어도 되는 건 다음 네 가지예요.

  • 이슈나 PR이 close(닫힘)되면 그 카드의 Status가 자동으로 Done으로 바뀌어요.
  • PR이 merge(병합)되면 역시 Status가 Done으로 바뀌어요.
  • Auto-add to project(프로젝트에 자동 추가) — 조건에 맞는 이슈·PR을 보드에 자동으로 올려줘요.
  • Auto-archive items(항목 자동 보관) — 조건에 맞는 오래된 항목을 보드에서 자동으로 치워(보관) 화면을 깔끔하게 해줘요.

즉 PR #57이 병합되면, 그 카드는 누가 옮기지 않아도 Done으로 미끄러져 들어가요. 위 mock에서 손으로 옮겨본 그 움직임을, 실제로는 자동화가 대신 해주는 셈이에요.

알아두면 좋은

자동화 목록은 조직·시점에 따라 달라져요. 위 네 가지 말고도 화면에 다른 규칙이 보일 수 있는데, 그 이름과 동작은 팀 설정에 따라 다르니 여기서 외우려 하지 마세요. 내 보드에 실제로 무엇이 켜져 있는지는 프로젝트 오른쪽 위 … 메뉴 → Workflows(워크플로)에서 직접 확인하세요. 거기에 켜고 끌 수 있는 규칙이 그대로 나와요.
