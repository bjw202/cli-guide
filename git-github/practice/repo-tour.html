실전 · P01 · GitHub 협업

저장소 한 바퀴, 나는 어느 탭에 사나

GitHub 저장소는 방이 여러 개 있는 사무실 같아요. 각 방(탭)이 무엇을 하는 곳인지 알면, 길을 잃지 않아요. 우리 팀의 '동네 도서관 웹사이트'를 예로 한 바퀴 둘러봐요.

비유

저장소(repository)는 팀이 함께 쓰는 사무실이에요. 문을 열고 들어가면 위쪽에 방 이름표가 죽 붙어 있어요 — 작업실, 요청 게시판, 검토실, 자동화실, 상황판. GitHub에서는 이 이름표를 탭(tab)이라고 불러요. 오늘은 이 방들을 하나씩 열어보기만 할 거예요. 안에서 뭘 하는지는 다음 페이지들에서 차근차근 배워요.

우리가 함께 볼 저장소와 세 사람

이 실전(P) 시리즈는 처음부터 끝까지 하나의 이야기를 따라가요. 매번 새 예제로 갈아타지 않으니 마음 편히 따라오세요. 무대는 이 저장소예요.

저장소: dongne-library/library-web — 동네 도서관 웹사이트를 새로 단장하는 프로젝트예요. 주소창에는 github.com/dongne-library/library-web 로 보여요. 앞의 dongne-library 는 '누구의 저장소인가'(조직 이름), 뒤의 library-web 은 '어떤 저장소인가'(저장소 이름)예요.

등장인물은 세 사람이에요. 이 중 지원 님이 우리(독자)의 분신이에요. 코드를 직접 짜지 않는 기획자이지만, GitHub 안에서 할 일이 아주 많답니다.

  • 지 지원 — 기획/PM. 코드는 안 짜지만 이슈를 열고, 우선순위를 정하고, 진행 상황을 챙겨요. 바로 여러분이에요.
  • 민 민수 — 개발자. 실제 코드를 고치고 PR을 올려요.
  • 하 하늘 — 디자이너. 화면과 버튼 모양을 챙기고, 민수의 PR을 리뷰해요.

상단 탭 다섯 방, 한 바퀴

저장소 위쪽 이름표를 왼쪽부터 열어볼게요. 지금은 '여긴 뭐 하는 방인지'만 기억하면 충분해요.

  • Code(코드) — 실제 파일과 폴더가 사는 방이에요. 개발자가 가장 많이 오가는 곳이죠. src/ 폴더, README 같은 소개 문서가 여기 있어요. 비개발자도 문서(README)를 읽거나 고칠 때 잠깐 들러요.
  • Issues(이슈) — '해야 할 일'과 '고쳐야 할 문제'를 적어두는 게시판이에요. "로그인 버튼이 안 눌려요" 같은 요청이 카드처럼 쌓여요. 지금 2 개가 열려 있네요.
  • Pull requests(풀 리퀘스트) — "이렇게 코드를 바꿨어요, 봐주세요"라는 변경 제안이 모이는 검토실이에요. 줄여서 PR이라고 불러요. 리뷰와 병합이 여기서 일어나요.
  • Actions(액션) — 자동화 로봇이 일하는 방이에요. 코드가 올라오면 자동으로 검사(테스트)를 돌려줘요. 비개발자가 매일 들를 곳은 아니에요. (자세한 건 T18에서요.)
  • Projects(프로젝트) — 포스트잇을 붙이는 상황판(칸반 보드)이에요. 할 일 · 진행 중 · 검토 · 완료로 카드를 옮기며 전체 진행을 한눈에 봐요. 기획자에게 아주 친한 방이에요.
팁

탭 이름 옆에 붙은 동그란 숫자(예: 2)는 '지금 열려 있는 항목 개수'예요. Issues 옆 2는 '아직 해결 안 된 이슈 2건', Pull requests 옆 1은 '검토를 기다리는 PR 1건'이라는 뜻이에요. 숫자만 봐도 어디에 일이 쌓였는지 감이 와요.

비개발자는 주로 어느 탭에 사나요?

다섯 방을 다 외울 필요는 없어요. 코드를 직접 짜지 않는다면, 여러분(지원 님)이 매일 사는 방은 세 곳이에요.

  • Issues — 요청과 문제를 적고, 담당자를 정하고, 진행을 추적해요. 여러분의 홈그라운드예요. (다음 페이지 P02에서 이슈 화면을 해부해요.)
  • Pull requests — 개발자가 올린 변경을 확인하고, 필요하면 의견(코멘트)을 남겨요. 승인 버튼을 함부로 누르지 않는 요령은 P05에서 배워요.
  • Projects — 팀 전체의 진행 상황을 상황판으로 관리해요. 카드 옮기기 하나로 회의가 짧아져요.

Code 와 Actions 는 '개발자·로봇의 방'이에요. 가끔 문서를 고치러 Code에 들르는 정도면 충분하고, 나머지는 곁눈으로 익숙해지면 돼요. 억지로 다 알려고 하지 마세요.

알아두면 좋은

이 시리즈의 화면들은 진짜 GitHub이 아니라, 학습용으로 다시 그린 '재현 화면'이에요. 창 왼쪽 위 신호등 점과 주소창이 그 표시예요. 실제 GitHub은 색과 위치가 조금 다를 수 있지만, 눌러야 할 자리와 이름은 똑같이 맞춰 두었으니 안심하고 눈에 익혀 두세요.

이렇게도 써요

꼭 코드가 아니어도 돼요. 동아리 회칙, 스터디 자료, 결혼 준비 체크리스트를 GitHub 저장소로 관리하는 사람도 많아요. 그때도 방 구성은 똑같아요 — 할 일은 Issues, 상황판은 Projects. 이름표만 익히면 어떤 저장소든 길을 잃지 않아요.
