이슈 화면 해부: 사이드바 9칸

이슈 하나를 열면 오른쪽에 아홉 개의 작은 칸이 줄지어 있어요. 처음엔 낯설지만, 각 칸이 '무엇을 정하는 자리'인지 알면 이슈 화면이 갑자기 쉬워져요. 우리 #42 이슈로 하나씩 짚어볼게요.

비유

이슈 화면은 병원 접수 차트 같아요. 왼쪽 넓은 칸에는 '어디가 어떻게 아픈지'(문제 설명)를 적고, 오른쪽 좁은 칸들에는 '누가 볼지, 어느 과인지, 언제까지인지' 같은 꼬리표를 붙여요. 이 오른쪽 꼬리표 묶음이 바로 오늘의 주인공, 사이드바(sidebar)예요.

이슈 #42를 열어봤어요

지원 님이 올린 이슈 #42 「로그인 버튼이 안 눌려요」를 열었어요. 왼쪽에는 문제 설명과 댓글이, 오른쪽에는 아홉 개의 칸(사이드바)이 보여요. 아래 화면에서 파란 핀(1~9)을 눌러보세요. 누른 핀에 해당하는 설명이 아래 목록에서 함께 켜져요. 반대로 목록을 눌러도 핀이 켜지고요. 어느 쪽을 눌러도 짝이 맞춰지니 편하게 눌러보며 익혀요.

지 민
  1. 핀을 누르면 이 설명이 켜져요 (핀 ↔ 설명 양방향)
  2. Assignees(담당자) — 이 이슈를 맡을 사람을 정해요. 톱니(⚙)를 눌러 민수를 지정했어요. "이건 누가 하나요?"의 답이에요.
  3. Labels(라벨) — 이슈에 붙이는 색깔 꼬리표예요. 톱니를 눌러 bug, priority:high 를 붙였어요. 종류·긴급도를 한눈에 보여줘요.
  4. Type(유형) — 이 이슈가 버그인지, 기능인지, 잡일인지를 정하는 공식 분류예요. 여기선 Bug. 라벨과 달리 조직이 정한 표준 유형이에요.
  5. Projects(프로젝트) — 이 이슈를 어느 상황판(보드)에 올릴지 골라요. 도서관 리뉴얼 보드 에 연결하면 카드로 나타나요. (P06에서 보드 운영을 배워요.)
  6. Milestone(마일스톤) — 이 이슈가 속한 목표 묶음이에요. v1.0 오픈 에 넣으면 그 출시의 진행률에 함께 집계돼요. (P07에서 다뤄요.)
  7. Sub-issues(하위 이슈, Relationships) — 큰 이슈를 작은 이슈로 쪼갤 때 쓰는 자리예요. Create sub-issue(하위 이슈 만들기) 버튼으로 자식 이슈를 달아요. #42는 하위 이슈가 없어요.
  8. Development(개발 연결) — 이 이슈를 고치는 브랜치나 PR을 연결하는 자리예요. PR #57을 이어두면 "이 문제를 지금 저 PR에서 고치는 중"이 보여요. (P04에서 수동 연결 경로를 배워요.)
  9. Notifications(알림) — Subscribe(구독) 를 누르면 이 이슈에 새 댓글이 달릴 때 알림을 받아요. 관심 이슈만 콕 집어 따라갈 수 있어요.
  10. Participants(참여자) — 이 이슈에서 이야기를 나눈 사람들의 얼굴이 모여요. 지원·민수가 보이네요. 누른다기보단 '누가 관여했나'를 알려주는 자리예요.
팁

사이드바 칸마다 오른쪽에 작은 톱니(⚙) 아이콘이 있어요. 그게 바로 '이 칸을 편집하는 버튼'이에요. 담당자를 바꾸고 싶으면 Assignees의 톱니, 라벨을 바꾸고 싶으면 Labels의 톱니. 규칙이 똑같아서, 하나만 익히면 아홉 칸을 다 다룰 수 있어요.

Labels와 Type, 뭐가 다른가요?

둘 다 '이슈를 분류하는' 자리라 헷갈려요. 차이는 이래요. Labels(라벨) 는 우리 팀이 자유롭게 만들어 여러 개 붙일 수 있는 색깔 꼬리표예요(bug, priority:high, design…). Type(유형) 은 조직 차원에서 정한 딱 하나의 공식 분류예요.

Issue types(이슈 유형)는 2025년 4월에 정식 출시됐어요. 기본으로 Bug(버그) / Feature(기능) / Task(작업) 세 종류가 준비돼 있고, 조직 관리자가 Settings(설정) → Planning(계획) → Issue types(이슈 유형) 에서 새 유형을 추가할 수 있어요. 한 조직당 최대 25개까지 만들 수 있어요.

# 조직에서 이슈 유형(Issue types)을 관리하는 경로
Settings  →  Planning  →  Issue types

# 기본 제공 3종
Bug      버그: 원래 되던 게 안 될 때
Feature  기능: 새로 만들고 싶은 것
Task     작업: 그 밖의 해야 할 잡일

# 조직당 최대 25개까지 유형을 만들 수 있어요

Sub-issues: 큰 일을 잘게 쪼개기

#42는 버튼 하나 문제라 단순하지만, 어떤 일은 너무 커서 이슈 하나로는 벅차요. 예를 들어 이슈 #38 「대출 연장 기능」은 화면·서버·알림까지 여러 갈래로 나뉘어요. 이럴 때 하위 이슈(Sub-issues)로 잘게 쪼개요.

#38에는 하위 이슈 3개가 달려 있고, 그중 1개가 완료됐어요. 그래서 진행률이 1/3 로 보여요. 부모 이슈를 열면 자식들의 체크 상태가 한눈에 모여, "이 큰 일이 얼마나 진행됐나"를 바로 알 수 있어요.

  • Create sub-issue(하위 이슈 만들기) 버튼으로 자식 이슈를 새로 만들거나, 이미 있는 이슈를 자식으로 붙여요.
  • 부모 하나에 하위 이슈는 최대 100개까지 달 수 있어요.
  • 하위 이슈의 하위 이슈처럼, 최대 8단계까지 중첩할 수 있어요. 너무 깊어지면 오히려 헷갈리니 2~3단계면 충분해요.
주의

하위 이슈를 너무 잘게 쪼개면, 카드가 수십 개로 불어나 오히려 관리가 더 힘들어져요. "따로 담당·마감을 정할 만큼 독립적인 일인가?"를 기준으로 쪼개세요. 그 정도가 아니라면, 이슈 본문에 체크리스트(- [ ] 항목)로 적는 편이 가벼워요.

알아두면 좋은

사이드바 아홉 칸을 전부 채워야 하는 건 아니에요. 대부분의 이슈는 Assignees · Labels · Type 세 칸만 정해도 충분히 잘 굴러가요. 나머지(Projects, Milestone…)는 팀이 그 기능을 쓰기 시작할 때 자연스레 채우면 돼요. 빈 칸을 부담스러워하지 마세요.
